# 微信聊天记录自动长截图（wechat-longshot）

自动滚动微信聊天记录并逐屏拼接，生成一张长图的 Android 应用。

- 目标平台：**Android 17 / API 37**（compileSdk=37，targetSdk=37，minSdk=26 覆盖 Android 8.0+）
- 语言：**Kotlin**（纯 Kotlin + AndroidX，不依赖第三方库）
- **停止条件完全由用户手动控制**：自动滑动过程中程序绝不自行判断是否到底、绝不自动停止；
  只有用户点击 **悬浮窗「停止」按钮 / 通知栏「停止截屏」按钮 / 主界面「停止并保存」按钮** 后才结束截屏并合成保存。

## 构建步骤（已在本机实测通过）

**已验证环境**：AGP 8.13.1 + Gradle 8.13 + JDK 17 + SDK Platform 37 + build-tools 36.0.0。
命令行构建 29s 成功，产物：`app/build/outputs/apk/debug/app-debug.apk`（约 5.7MB）。

1. **Android SDK 要求**：需存在 `platforms;android-37`。若本机 SDK 中平台目录名为
   `android-37.0`（如某些渠道安装的 SDK），需复制一份为 `android-37` 并修正两个文件：
   - `source.properties`：`AndroidVersion.ApiLevel=37.0` → `37`
   - `package.xml`：`path="platforms;android-37.0"` → `path="platforms;android-37"`
2. 用 **Android Studio**（Otter 或更新）打开本项目根目录（`wechat-longshot/`），
   等待 Gradle 同步完成（推荐版本组合：AGP 8.13.1 + Gradle 8.13 + Kotlin 2.0.21）。
3. 连接真机（本应用依赖无障碍手势 + 屏幕录制 + 悬浮窗，真机体验最佳），点击 Run 安装；
   或命令行直接取用已构建的 debug APK 安装。

## 真机使用步骤

1. 打开微信，进入要截取的聊天记录，**停留在最上方**。
2. 回到「微信长截图」App，确认三项状态（无障碍 / 悬浮窗 / 通知）均已开启；
   点击 **开始截屏**：
   - **Android 11+（推荐）**：无障碍已开启时**无需录屏授权**，直接进入"无障碍截图模式"，
     自动开始滚动；首次会引导开启**无障碍服务**与**通知/悬浮窗**。
   - **Android 8~10 或无障碍未开启**：走 MediaProjection 路线，弹系统**屏幕录制**授权框
     （每次会话都要授权一次），允许后自动开始。
3. 截屏开始后，App 会自动向上滚动并逐屏拼接（可切回微信查看滚动效果）。
   - 悬浮窗右上角显示已截屏数 + 「停止」按钮；通知栏常驻通知显示进度 + 「停止截屏」按钮。
4. 想结束时（比如滚动到了想截取的位置），点击**任意一个停止入口**：
   - 悬浮窗「停止」；
   - 通知栏「停止截屏」；
   - 回到 App 点「停止并保存」。
5. 保存完成后通知栏出现「长截图已保存，点击查看」；图片保存在相册
   `Pictures/LongScreenshots/微信长截图_yyyyMMdd_HHmmss.png`。

## 截图引擎：双路线设计

| 路线 | 适用 | 截图方式 | 是否需要录屏授权 |
| --- | --- | --- | --- |
| **无障碍截图模式**（推荐） | Android 11+，无障碍已开启 | `AccessibilityService.takeScreenshot()` | ❌ 不需要 |
| MediaProjection 模式 | Android 8~10，或无障碍未开 | MediaProjection + ImageReader | ✅ 每次会话授权 |

- 无障碍截图免授权的关键：`accessibility_service_config.xml` 声明了 `canTakeScreenshot="true"`。
- 无障碍截图受系统限流（两次间隔过短会出错 `INTERVAL_TIME_SHORT`），代码会自动拉长间隔重试（最多 3 次）。
- 遇到"提示没有截图权限"？先确认是无障碍模式还是录屏授权被拒：无障碍模式不需要任何录屏授权，
  点「开始截屏」后直接滚动即为无障碍模式；若走了录屏弹窗请允许"屏幕录制"。

## 权限清单

| 权限 | 用途 | 授权方式 |
| --- | --- | --- |
| `BIND_ACCESSIBILITY_SERVICE`（无障碍服务） | 模拟拖动自动滚动 | 系统无障碍设置页 |
| 屏幕录制（MediaProjection） | 截取屏幕帧 | 每次会话系统弹窗授权 |
| `SYSTEM_ALERT_WINDOW` | 悬浮停止按钮 | 系统悬浮窗设置页 |
| `POST_NOTIFICATIONS`（Android 13+） | 进度通知与停止按钮 | 运行时授权 |
| `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_MEDIA_PROJECTION` | 前台截屏服务（type=mediaProjection） | Manifest 声明 |
| `WRITE_EXTERNAL_STORAGE`（仅 Android 8~9） | 写入相册 | Manifest 声明（10+ 走 MediaStore 无需） |

## 设置项说明

- **滑动距离（内容高百分比，默认 60）**：每次拖动滚动的距离。越大滚动越快，但重叠越少、
  拼接容错越低；越小越稳、越慢。范围 10~90。
- **截图间隔（毫秒，默认 700）**：滚动完成到截图之间的等待，给列表稳定时间。网络/图片较多
  时可调大（如 1000~1500）。
- **输出缩放（0.5~1.0，默认 1.0）**：长图输出宽度 = 屏幕宽度 × 缩放。长截图超长时建议调低
  到 0.75 或 0.5，可显著降低内存与文件体积。
- **内存保护张数（默认 200）**：达到该屏数后自动暂停并提示「是否停止或继续」。
  这是**内存保护**而非"滚动到底"判定；用户可继续截图或停止保存。

## 内存控制说明（Android 17 内存限制器）

Android 17 按设备总 RAM 对应用进程设硬性内存上限，超限直接杀进程。本应用针对长图拼接
这一最大内存风险做了以下控制：

1. 拼接画布用 **ARGB_8888 真彩色**（每像素 4 字节）：微信浅色背景/文字对色深敏感，
   RGB_565 会出现色带导致画面发糊，故弃用；画质优先
2. 支持按比例缩放输出宽度（默认 1.0，可调低如 0.75x / 0.5x）——
   超长截图建议调低以控制内存
3. 单张位图拼接后**立即 recycle()**，不积压；
4. 达到内存保护阈值（累计高度约 45000px 或默认 200 张）自动暂停并 Toast 提示，
   用户可选择停止或继续；
5. 拼接在独立后台线程，避免阻塞主线程/截图循环。

## 停止为何完全由用户控制

`CaptureService` 的循环是：

```
滑动(dispatchGesture 完成) → 等稳定(可配间隔) → 截图 → 交给拼接线程 → 继续循环
```

循环中**没有**"是否到底部"的图像检测，也没有自动停止逻辑。任何停止入口
（悬浮窗/通知栏/主界面）最终都发 `ACTION_STOP` → 服务停止循环 → 拼接线程排空完成 →
保存 → 通知「已保存」。内存保护暂停是防 OOM 的**保护措施**，同样不代替用户决定何时停止。

## 技术要点

- **拖动（drag）而非 fling**：微信列表对拖动是"跟手"滚动、无惯性，滚动距离 ≈ 手势距离，
  拼接偏移更可控。手势：起点 x=屏幕中心、y=内容区 60% 处，终点 y=内容区 15% 处
  （按滑动距离比例计算），按住后立即移动避免长按弹出菜单。
- **行匹配去重**：新图顶部逐行（像素差 hash）与旧图底部区域匹配，搜索范围 = 滑动距离 ±20%，
  找不到可靠匹配时退化为固定裁剪（= 滑动距离）；匹配时跳过纯状态栏行。
- **MediaProjection（Android 14+/15+ 合规）**：先 `createScreenCaptureIntent()` 授权 →
  启动前台服务（type=mediaProjection）→ 服务内 `getMediaProjection()` → **立即
  `registerCallback()` 再 `createVirtualDisplay()`** → 使用 `MediaProjectionConfig`
  （API 34+）→ ImageReader（RGBA_8888）取帧转 Bitmap，每帧 `image.close()`。
- **大屏方向限制（targetSdk 37）**：sw>600dp 设备忽略 `screenOrientation`/`setRequestedOrientation`。
  手机（<600dp）上仍可锁定方向：开始前若为横屏会提示"请竖屏使用"，并建议关闭系统自动旋转。

## 小米 / HyperOS 设备说明

### 为什么不用小米系统自带的"长截图"
- **微信聊天窗口内系统长截图按钮是置灰的**：MIUI/HyperOS 的滚动截屏依赖应用适配 `ScrollCapture` 滚动锚点；
  微信聊天列表采用自定义渲染，系统拿不到滚动边界信息，长截图入口直接不可用（这是系统侧限制，用户无法绕过）。
- **即使可用也有硬限制**：系统滚动截屏深度上限约 9000~10000px（聊天记录通常远超）；且滚动/结束均由系统 UI 接管。
- **无公开 API**：小米没有开放任何第三方 App 调用系统滚动截屏或接管其"何时结束"的接口。

### 本应用在小米设备上的使用（无障碍截图模式）
1. 推荐走**无障碍截图模式**（Android 11+）：免录屏授权，不受系统滚动截屏限制，结束完全由你控制。
2. 无障碍服务开启后，建议：设置 → 应用 → 微信长截图 → **省电策略设为「无限制」**，避免被系统后台清理停用。
3. 悬浮窗权限：设置 → 应用 → 微信长截图 → 其他权限 → **显示在其他应用上层**（若系统提示"悬浮窗被禁止"请允许）。
4. 若反复提示"截屏初始化失败"，到设置 → 无障碍 → 微信长截图 → 关闭再重新开启一次即可。

## 已知限制与注意事项

1. **横屏 / 自动旋转**：请竖屏使用；截屏过程中请勿旋转屏幕（建议关闭自动旋转），
   否则画面方向变化会导致拼接错位。
2. **每次会话都要授权屏幕录制**：系统强制，无法绕过。
3. **悬浮窗权限**：需在系统设置手动开启；未开启时没有悬浮停止按钮
   （仍可用通知栏/主界面停止）。
4. **微信深色模式**：深色背景下行匹配 hash 仍然有效，但纯黑区域对行匹配更敏感；
   建议浅色模式下使用。
5. **Android 8~9（API 26~28）**：保存到公共相册依赖 `WRITE_EXTERNAL_STORAGE`，
   Manifest 已声明；如被系统限制，请手动授权存储。
6. **长图过大**：超过设备解码上限（约 16000px 高度）时，相册可能无法完整显示/解码，
   建议调低输出缩放或分批截图。
7. **微信更新可能影响滚动**：微信列表结构若变化（如新增头部组件），自动滚动仍可工作
   （无障碍手势与 UI 结构无关），但拼接重叠行匹配的稳定性可能下降。
8. **无障碍服务需保持开启**：若用户在系统设置中关闭了无障碍服务，循环会提示
   「无障碍手势执行失败」，此时内容不滚动、截图重复；请重新开启服务并重新开始。
